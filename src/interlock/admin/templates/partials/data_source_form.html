Source roles

Roles are managed after the source is created. InterLock can create conservative default role templates to edit later.

Network

Allow a source on a private network, such as a Docker Compose service or a VPC address. InterLock refuses private addresses unless a source opts in; every use is logged.

Snowflake sources use the official Python connector. Prefer password or private-key secret refs for production.

Use Amazon S3 or any S3-compatible provider. For DigitalOcean Spaces, use the Spaces endpoint URL, for example https://nyc3.digitaloceanspaces.com.

For Zendesk, use subdomain or base URL plus email and API token ref. Optional scope fields limit discovery and role dry-run metadata.

For Slack, use workspace plus bot token ref. Discovery is read-only and can include channels, messages, thread replies, and files.

Google Workspace uses the gws CLI behind InterLock governance. Start read-only with Drive, Gmail, Calendar, Chat, or Admin Reports scopes.

Use OpenSearch/Elasticsearch for indices and documents, or Qdrant for collections and points.
